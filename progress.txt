WHY THIS EXISTS
---------------
Firehose must trace pre-execution system calls (EIP-4788 beacon-root,
EIP-2935 block-hash history). Stock alloy-evm does NOT route system calls
through the Inspector: `EthEvm::transact_system_call` (crates/evm/src/eth/mod.rs)
calls `self.inner.system_call_with_caller(...)` unconditionally. So with stock
alloy-evm the firehose inspector never sees the system-call frame.

To fix this the valve fork patches alloy-evm via reth's `[patch.crates-io]` to a
fork that adds:

    fn transact_system_call(&mut self, caller, contract, data) {
        if self.inspect {
            self.inner.inspect_system_call_with_caller(caller, contract, data)
        } else {
            self.inner.system_call_with_caller(caller, contract, data)
        }
    }
    // + import revm::InspectSystemCallEvm

WHY WE CAN'T FOLD BACK TO UPSTREAM YET
--------------------------------------
- Upstream PR: alloy-rs/evm#323 "Enable system call to be traced by inspector"
  (StreamingFast / Matthieu Vachon) — this is the SAME change our fork carries.
- As of 2026-06-15 #323 is OPEN, unmerged. The latest upstream release is
  v0.37.0 and `upstream/main` STILL has the un-inspected system_call_with_caller.
  There is no upstream version we can switch to.
- Merge is blocked on a maintainer concern (klkvr, alloy member):
    "i think we should make sure that any reth rpc callsites explicitly disable
     inspection before pre/post execution hooks before making this change"
  Rationale: inspecting system calls is a HIDDEN behavioral change for callers
  that don't want them. geth does NOT trace system calls in debug_traceBlock
  (it builds the pre/post EVM without a tracer). Landing this upstream first
  requires auditing reth's RPC callsites (e.g.
  crates/rpc/rpc-eth-api/src/helpers/trace.rs and likely others) to explicitly
  disable_inspector around apply_pre/post_execution_changes. That is cross-repo
  work into reth itself, not a one-liner.

KNOWN SIDE-EFFECT OF OUR PATCH (the maintainer's concern, applied to our build)
------------------------------------------------------------------------------
Because our patch inspects system calls whenever `self.inspect` is set, valve's
debug_traceBlock / trace_* RPC endpoints will ALSO surface the EIP-4788/2935
system calls — a divergence from geth on those endpoints. Correct/required for
firehose; possibly over-tracing for the debug RPC. Has not broken anything
(122/122 valve regression tests pass), but it is exactly why upstream wants the
callsite guards before merging.
